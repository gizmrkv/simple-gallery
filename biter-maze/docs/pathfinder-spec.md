# バイター経路探索の仕様

このプロジェクトが再現しているFactorioの経路探索の中身と、**意図的に再現していない
部分とその理由**をまとめる。実装は[`src/pathfinder.ts`](../src/pathfinder.ts)。

## 出典と実パラメータ

数値はすべてFactorio公式の`map-settings.example.json`（[wube/factorio-data](https://github.com/wube/factorio-data/blob/master/map-settings.example.json)）
の`path_finder`セクションから取った。意味の説明は
[PathFinderSettings](https://lua-api.factorio.com/latest/types/PathFinderSettings.html)、
[PathfinderWaypoint](https://lua-api.factorio.com/latest/concepts/PathfinderWaypoint.html)、
[FFF #317](https://www.factorio.com/blog/post/fff-317)による。

| パラメータ | 公式既定値 | 本実装 | 扱い |
| --- | --- | --- | --- |
| `goal_pressure_ratio` | 2 | 2 | `f = g + ratio*h`。**重み付きA\***なので最短経路とは限らない |
| `general_entity_collision_penalty` | 10 | 10 | 壁タイルに侵入するコスト加算 |
| `general_entity_subsequent_collision_penalty` | 3 | 3 | 直前も壁だった場合はこちら |
| `extended_collision_penalty` | 3 | **既定0** | 解釈が不確かなため既定を下げた（後述） |
| `fwd2bwd_ratio` | 5 | — | **意図的に未実装**（後述） |
| `short_request_max_steps` | 1000 | 既定0=無制限 | `Max expansions`として公開 |

## 最重要の前提: 壁は通行不能ではない

**Factorioのバイターは壁を「通れない障害物」とは見なさない。「コストを払えば通れる
もの」と見なす。** `PathfinderWaypoint`に`needs_destroy_to_reach`
（「直前の地点からこの地点への経路が、破壊しなければならないエンティティを通る」）
というフラグがあるのがその証拠で、経路探索の結果そのものが破壊を含みうる。

壁1枚を壊すコストは10 ≒ **10タイル分の迂回**。したがって:

- 迂回が10タイル分未満で済むなら、バイターは迂回する。
- 迂回のほうが高くつくなら、バイターは壁を壊して直進する。

この綱引きが本プロダクトの最適化問題そのものである。「壊されない範囲で最も長い
迂回を強いる配置」を探すことになる。

## 盤面のトポロジ: 左右はつながっている

盤面は **x方向に巡回する円筒**として扱う。`x = -1` は `x = W-1` に、`x = W` は
`x = 0` につながる。上下は巡回しない（上端がバイターの侵入口、下端がゴール）。

理由は運用側にある。この迷路は**設計図として横方向に繰り返し建築する**ことを想定して
いるので、実際の防衛線では同じ形の迷路が左右に無限に並ぶ。左右を独立した壁として
シミュレートすると、盤の端付近のレーンだけが「行き止まりに追い込まれる」という
実物には存在しない有利さを得てしまい、探索結果が実際の建築と食い違う。

実装上の影響:

- 近傍生成・`nearWall`の構築・角抜け判定の肩タイルすべてでxを巡回させる（`wrapX`）。
- **迂回距離は巡回距離 `min(d, W-d)` になる。** W=16なら横方向の最大迂回は8タイルで、
  これは`collisionPenalty = 10`を下回る。つまり**横に逃げるだけでは貫通の敷居を
  超えられない**ので、迂回コストを稼ぐには縦方向の蛇行が必須になる。
  この性質のおかげで、GAは「端で行き止まりにする」ではなく「経路を縦に引き延ばす」
  方向に素直に向かう。
- 描画では、端をまたぐ区間を盤外まで引いてから反対の端で引き直し、バイターは
  連続座標で補間してから左右だけ折り返す。

## コストモデル

タイル`i = y*W + x`、壁マスク`walls: Uint8Array(W*H)`。

```
cost(u → v) = step(u,v)                                           // 直交1 / 斜め√2
            + (wall[v] ? (wall[u] ? subsequentPenalty : collisionPenalty) : 0)
            + (nearWall[v] ? extendedPenalty : 0)

h(v) = goalPressureRatio * (H-1-y)
f    = g + h
```

- `nearWall[v]` = vは非壁で、8近傍のいずれかが壁。
- **ゴールが下端行全体**なので、最近ゴールまでのユークリッド距離は厳密に垂直距離
  `H-1-y`に一致する。
- **スタート**: バイターは盤外（`y=-1`、自由空間）から侵入してくる扱い。よって
  上端行のセルが壁なら「直前は壁ではない」＝通常の`collisionPenalty`を払う。
  スタートタイルを無料にすると、GAが即座に「上端行を壁で埋める」抜け道を見つける。

### 破壊枚数と移動距離は別々に積算する

適応度が使うのは`travel`（**移動距離のみ**、ペナルティ除外）であって`g`ではない。
ペナルティは仮想コストなので、`g`を最大化すると「壁際を多く踏む」という実利のない
設計に報酬が出てしまう。詳細は[ga-spec.md](ga-spec.md)。

## 状態空間を拡張する必要はない（重要）

「subsequentペナルティは直前が壁かどうかに依存するのだから、ノードを
`(タイル, 直前が壁か)`の2倍に拡張しないとA\*が成り立たないのでは」という疑問が
出うるが、**拡張は不要**。

拡張が必要になるのは「vから出る辺のコストが、vにどう入ったかに依存する」場合だけ
である。ここで`cost(v→w)`は`wall[v]`, `wall[w]`, `nearWall[w]`, `step(v,w)`のみの
関数であり、`wall[]`は静的。**辺コストは経路履歴に依存しない＝マルコフ性は破れて
いない。** 単に辺依存コストを持つ有向グラフであり、素のA\*がそのまま正しい。

誤解しやすいのは公式の文言が「破壊を要する位置の*後続*へのペナルティ」となっている
点だが、「位置vが破壊を要するか」はvだけの性質（ユニットのbboxをvに置いたとき破壊
対象と重なるか）であって、どの辺でvに来たかには依存しない。

なお、辺コストは**非対称**である（uが床・vが壁なら`cost(u→v)=d+10`だが
`cost(v→u)=d+0`）。これは有向グラフなので、逆向き探索を使う場合は転置グラフが要る。

## 角抜け（コーナーカット）は禁止

斜め移動`(dx,dy)`は、肩タイル`(x+dx, y)`と`(x, y+dy)`の**どちらかが壁なら不許可**。

「壁は通過可能なのに斜めは塞ぐのか」という点の整理: 2枚の壁が角で接しているとき、
その対角の隙間の幅は0であり、有限の当たり判定を持つユニットは通れない。壁を通り
抜けたいなら直交移動で壁タイルに入り、ペナルティを払う必要がある。この規則が
**「壁を通り抜ける唯一の方法は必ずペナルティを払うこと」**というコスト意味論を守る。

この規則が無いと、GAは市松模様の壁配置が実質無コストであることを即座に学習して壊れる。
`src/pathfinder.test.ts`の「角抜け禁止」テストがこれを守っている。

`Allow diagonal`をOFFにすると全コストが整数になり、浮動小数の同点問題が完全に消える。
デバッグ・検証用として有用。

## 実装していないもの

### 双方向探索（`fwd2bwd_ratio = 5`）

**意図的に未実装。** 理由は複雑さではなく忠実性にある。

`goal_pressure_ratio = 2`は**inadmissible（重み付き）ヒューリスティック**である。
双方向A\*の正当性（NBS/MM系）の文献上の議論はすべてadmissible前提であり、重み付き
ヒューリスティック下には健全な停止・合流条件が存在しない。つまりFactorioのC++実装は
必ず非公開のアドホックな合流規則を持っているはずで、公開されている数値（比率5）
1つからそれを推測して書いたものは「もっともらしい再構成」にすぎない。

**推測で埋めた実装を「忠実な再現」として提示するほうが、実装しないより不誠実**だと
判断した。公開されている部分（重み付きランキングと衝突ペナルティ）は正確に実装し、
非公開の部分はここに明記する。

なお、本プロダクトの問い（バイターが壊すか迂回するか）を決めているのはコストモデル
（10 / 3 / 3）と重み付きランキングのほうであって、探索の進め方ではない。

### `extended_collision_penalty` を既定0にしている理由

公式の既定値は3だが、これは「ユニットの**拡張**バウンディングボックスでの衝突、ただし
実際のbboxの外側」に対する判定である。1セル=1タイルのグリッド近似では、これは
「壁に8近傍で接するタイルに入るとき一律+3」という解釈にならざるをえず、これは
**推測に基づいたかなり強い構造的主張**になる。

具体的には、幅1の通路は1タイルあたりの実効コストが1→4（4倍）に跳ね上がり、
「幅1の通路は最悪、幅3なら中央レーンが無料」という迷路設計上の大きな歪みが生じる。

そこで**既定0**で挙動を素直にし、スライダー（0〜5）で実験できるようにした。
Factorio本来の挙動に寄せたい場合は3に設定すること。0⇄3で切り替えると、バイターが
壁際を舐めるか避けるかが目に見えて変わる。

## 決定性

同じ盤・同じパラメータなら必ず同じ経路を返す。そのための仕掛けは2つ:

1. **ヒープの比較は3キー辞書順** `(f昇順, g降順, nodeId昇順)`。f同点でgが大きい方を
   先に出すのは展開数を減らす定石で、最後のnodeIdで完全な決定性を得る。
2. **緩和条件に同点破りを入れている**:
   `ng < g[v]-EPS || (ng < g[v]+EPS && ntravel < travel[v]-EPS)` （`EPS = 1e-9`）。
   コスト同点の経路が複数あるとき**travelが小さい方**を採る。これは防御側にとって
   悲観的な仮定であり、適応度が運のいい同点破りで水増しされないようにしている。

展開済みノードは**再オープンしない**（重み付きA\*の標準的な挙動）。
`goalPressureRatio = 1`のときヒューリスティックはadmissibleかつconsistentなので、
この場合のA\*の結果は厳密な最小コスト経路に一致する。
`src/pathfinder.test.ts`の「Dijkstraオラクル」テストがランダム盤50枚でこれを確認し、
`= 2`のときは`cost_astar >= cost_dijkstra`が成り立つことも併せて確認している。

## 迷路設計への含意（実測）

GAを回すと、**厚い壁より散らばった薄い壁（いわゆるdragon's teeth）が強い**という
結果になる。理由はコストモデルから直接出る:

- 厚さkの壁を直進で貫くコストは `10 + 3(k-1)`（2枚目以降は3）。
- 孤立した1枚壁をk枚踏むコストは `10k`（毎回「直前は壁ではない」ので10）。

つまり同じk枚でも、**連続した壁より散らばった壁のほうが3倍以上高くつく**。
実測（16x16・既定パラメータ・pop 100）では、壁64枚で全16レーンが破壊0のまま
travel 37〜44（直進15に対して約2.5〜3倍）に収束した。

達成可能なtravelの上限は「直進貫通コスト」で頭打ちになる。物足りなければ
`Collision penalty`を上げるとよい。

左右が巡回しているため横方向の迂回は最大でも`W/2`タイルしか稼げない。したがって
稼ぎどころは縦方向の蛇行であり、GAが作る迷路も縦に折り返す構造になる。

## モデル全体のサニティチェック

GUIで以下が成り立たなければコストモデルが壊れている:

- `Collision penalty`を50にする → 破壊が完全に止まり、純粋な迂回になる。
- `Collision penalty`を1にする → ほぼ全レーンが貫通し、適応度が直進コスト付近まで崩壊する。
