# 遺伝的アルゴリズムの仕様

迷路（壁配置）を探索するGAの設計と、既定値をそう決めた理由。実装は
[`src/ga.ts`](../src/ga.ts)・[`src/fitness.ts`](../src/fitness.ts)・
[`src/evaluator.ts`](../src/evaluator.ts)。

## 適応度

```
score_s = travel_s - breakPenalty * breaks_s          // s = 上端行の各セル（レーン）
fitness = alpha * min_s(score_s)
        + (1 - alpha) * mean_s(score_s)
        - wallCost * wallCount
```

最大化する。全タイルが通過可能（壁も壊せば通れる）なので**経路探索は必ず成功する**。
`Max expansions`で打ち切ったときだけ未到達になり、そのレーンは大きな負スコアになる。
不到達の特別扱いが要らないのは設計上のご褒美なので、ここに明記しておく。

### なぜ`travel`（移動距離のみ）を使い、`g`（ペナルティ込み）を使わないのか

ペナルティは**仮想コスト**である。壁のそばを歩いてもバイターの実際の歩行時間は
増えない。`g`を最大化すると「壁に隣接するタイルを多く踏ませる」という実利のない
設計に報酬が出てしまう。`travel`を使うことで目的関数が「実際に歩く距離」に一致し、
かつ`travel ≤ g`なので評価は常に保守的になる。

### なぜ破壊が「減点」なのか（物理ではなく設計上の選好）

壁をかじる時間はバイターにとってはむしろ遅延であり、防御側には有利なはずである。
それでも減点するのは、**壁を壊されたら再建が要る／バイターを迷路に閉じ込めて
タレットの射線に通したい**という設計意図による。これは物理コストではなく
**設計上の選好**である。この一文が無いと符号を疑うことになるので残しておく。

### なぜ「無効化」ではなく「枚数比例の減点」なのか

ランダム初期集団のほぼ全個体が、最低1本は破壊するレーンを持つ。1枚でも壊したら
無効化する方式だと初期集団の適応度が定数になり、**選択圧がゼロ＝ランダムサーチ**に
なる（制約付きGAで有名な death penalty の失敗パターン）。

加えて破壊は0/1ではない。1回と5回は違うし、「travelは長いが破壊1回」の個体は交叉で
修復されうる貴重な素材である。殺してはいけない。

### なぜ min と mean のブレンドなのか

- **純min（alpha=1）** は防御としては正しい目的（最弱の侵入口が防御力を決める）だが、
  max-min目的はGAにとって**平坦**である。16レーン中15本を改善しても最弱が動かなければ
  適応度が1ミリも上がらず、選択圧が消えてドリフトする。
- **純mean（alpha=0）** は勾配は出るが、「15本は長いが1本だけ素通し」という穴あき迷路に
  収束する。
- ブレンドはこの緊張を解く標準的な緩和。

適応度は負値を取りうるので、**選択はランクベース（トーナメント）でなければならない**。
ルーレット選択は負値で破綻する。

### 既定値

| パラメータ | 既定 | 根拠 |
| --- | --- | --- |
| `alpha` | 0.5 | min と mean を等分。最弱レーンを重視したいなら0.7程度まで上げるとよい |
| `breakPenalty` | 30 | 「1回の破壊を正当化するには30タイル分の追加歩行が要る」。16x16の直進は15、実測の到達点は40前後なので十分支配的 |
| `wallCost` | 0.1 | 小さくてよい。壁だらけの盤は`breakPenalty`が既に強烈に罰する。役割は倹約圧（浮いた無意味な壁の除去）と、同点解の平坦域を潰して収束を助けること |

## 遺伝子表現

**1セル1バイトの`Uint8Array`。ビットパックはしない。**

- 16x16なら256B/個体、pop 100で25KB。無視できる。
- ビットパックするとA\*の最内周（8近傍参照×数千回展開）ごとにシフト＋マスクが入る。
  8倍のメモリ節約に見合わない。
- 集団は**1本のフラットな`Uint8Array(popSize * n)`**（個体iは`i*n`から）。
  workerへのチャンク送出が`slice`一発になる。

## 演算子

### 交叉: ブロック交叉のみ

x方向2点・y方向2点で矩形を選び、確率0.25で全幅・確率0.25で全高に広げる。
これ1つで**行バンド交叉／列バンド交叉／矩形ブロック交叉**の3種類が、ノブを増やさずに出る。

一様交叉は採用しない。適応度を決めているのは**連続した壁構造（空間的に連鎖した遺伝子）**
であり、一様交叉はそのビルディングブロックを最大限に破壊する。

### 突然変異: 2段構え

1. **セル反転** — UI上は「1個体あたりの反転ビット数」（既定2.0）で公開し、内部で
   `p = bits / n`に変換する。per-cell確率を直接スライダーに出すと桁が小さすぎて
   操作不能になるため、この変換はUX上重要。
2. **構造変異**（既定0.2） — 子1体につき高々1回、
   {線を引く／**線を消す**／矩形を埋める／**矩形を消す**} から一様に選ぶ。

「消す」系が無いと、ビット反転だけで壁の「線分」を作るにはO(L)回の協調した変異が
必要になり実質到達不能になる。また**「ここを突破されてしまう」局所最適から抜けるには、
壁の塊を一度消す必要がある**。

### 選択・エリート・多様性

- **トーナメント選択 k=3**。負の適応度で動き、圧力を調整でき、O(1)で、完全に決定的。
- **エリート4（重複排除つき）**。FNV-1aでゲノムをハッシュし、既選出エリートと同じなら
  次点を採る。これが無いとエリート4枠が同一個体のコピー4つで埋まる（交叉で頻発する）。
- **ランダム移民2%**。毎世代、末尾スロットを新規ランダム個体で置換する。早期収束に
  対する最も安い保険。

**この問題は中立ネットワークが巨大**である。バイターが一度も踏まないタイルの壁は
適応度に一切現れないため、遺伝的には違うが適応度が同じ個体が大量発生する。
`wallCost`の倹約圧＋エリート重複排除＋移民の3点セットがこれに対応している。

### 初期化

一様ランダム（密度0.5）だけにはしない。構造のないノイズになり初期適応度が悲惨で
立ち上がらない。**50/50混合**:

- 半数: 個体ごとに`p ~ U(0.1, 0.5)`を引いてベルヌーイ（密度の多様性を初手で確保）
- 半数: ランダム線分を`U(3,10)`本描く（第0世代から壁らしいビルディングブロックを持たせる）

混合比は内部固定でノブにしていない。

## 決定性の契約

**乱数を消費するのは`Ga`だけ。評価（`evaluateChunk`）は純関数。**

評価が`(genome, params) → stats`の純関数なので、結果を`first + index`で再組み立て
しさえすれば、**worker数・完了順・マシンに依存しない**。これにより動的負荷分散を
自由に使える（迂回の長い迷路はA\*の展開数が数倍になるため、静的分割だと遅いチャンクを
引いたworkerで全体が待たされる）。

`src/ga.test.ts`の「評価の完了順やチャンク分割に依存しない」テストが、チャンクを
ランダムに刻んでランダム順で評価する評価器と同期評価器の結果が完全一致することを
確認している。GUI上では**Worker countを1と8で切り替えて同じシードでResetし、
同じ世代のbestが一致すること**で確認できる。

ソートは必ず`(−fitness, index)`の明示的2キー比較で行い、`Array.prototype.sort`の
安定性に暗黙に頼らない。

### 例外: 注入はシード再現性を壊す

ユーザーが描いた迷路の注入はユーザーイベントなので、シードだけからのビット単位の
再現性は成り立たなくなる。隠れた非決定性として扱われないよう明記しておく。

注入は**世代交代の末尾で行い、最下位スロットを置換する**。以後その個体は他の個体と
まったく同様に交叉・選択・淘汰される。

## 実測と調整の指針

16x16・既定パラメータ・pop 100（1スレッド）での実測:

```
gen    0: best = 17.7
gen  100: best = 32.4
gen  300: best = 34.4
gen  600: best = 34.9   （以後ほぼ横ばい）
```

到達点は壁67枚・**全16レーンが破壊0**・travel 39.8〜47.2（直進15に対して約2.7〜3.1倍）。

盤面の左右がつながっているため横方向の迂回は最大`W/2 = 8`タイルしか稼げず、
これは`collisionPenalty = 10`を下回る。つまり**横に逃がすだけでは貫通の敷居を
超えられない**ので、GAは縦方向の蛇行でコストを稼ぐ構造に収束する。
交叉のx範囲と構造変異の横線も巡回させてあり、x=0/x=W-1 の継ぎ目にだけ
組み換えが起きないという人工的な偏りは無い。

プラトーに乗ったときに動かすノブ:

| 症状 | 対処 |
| --- | --- |
| 全レーンが伸びているのにfitnessが動かない | `alpha`を下げる |
| 1本だけ極端に短いレーンが残る | `alpha`を上げる |
| 早期に収束して動かない | `Immigrant rate`を上げる / `Tournament size`を下げる |
| 迂回がもっと欲しい | `Collision penalty`を上げる（貫通の敷居が上がる） |
| 破壊される個体ばかり | `Break penalty`を上げる。0にすると「純travel最適」＝バイターが蛇行路を貫通してくる様子が見られ、このペナルティの存在理由のデモになる |

## 並列化

- プールサイズは`min(hardwareConcurrency, 8)`。これほど小さいジョブではpostMessageの
  オーバヘッドが支配的になるため8で打ち止めにしている。UIで1〜コア数まで変更可能。
- チャンク数は`workerCount * 2`。空いたworkerに1つずつ投入して動的に均す。
- `new Worker`が例外を投げる環境では**mainスレッド同期評価にフォールバック**する
  （公開デモなので落ちるより遅いほうがよい）。実測で同期でも50 gen/s程度は出る。
- **transferableの罠**: `postMessage(buf, [buf])`の後、送信側のArrayBufferはdetachされる。
  集団バッファ本体を転送してはいけない。必ず**チャンクのコピー**を転送し、worker側も
  返信のたびに新しいバッファを確保する。
- エリートの適応度キャリーオーバーはしない。全個体を毎世代再評価することで、
  「走行中に経路探索・適応度パラメータを変えたら次世代から自動的に新しい基準になる」
  という挙動が無料で手に入る。これはUI要件に直結する利得で、数%の計算節約より価値が高い。
